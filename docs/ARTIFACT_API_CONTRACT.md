# Контракт API артефактов проекта ERA5-Minimum

**Версия:** 0.1.0

---

# 1. Назначение

Настоящий документ определяет контракт JSON-артефактов проекта **ERA5-Minimum**.

Контракт предназначен для обеспечения единого интерфейса взаимодействия между:

- ML-пайплайном;
- Backend (FastAPI);
- Frontend.

Backend получает JSON-артефакты, сформированные ML-компонентом, выполняет их валидацию и предоставляет данные через REST API.

Данный документ является **единым источником истины** (Single Source of Truth) относительно структуры артефактов.

---

# 2. Область применения

Контракт определяет структуру следующих артефактов:

- summary;
- experiments;
- sample_efficiency;
- reconstructions.

Настоящий документ **не описывает**:

- архитектуры моделей;
- формат хранения ERA5;
- NetCDF-файлы;
- процесс обучения моделей;
- промежуточные чекпоинты;
- внутреннюю реализацию компонентов.

---

# 3. Структура набора артефактов

Backend ожидает следующую структуру файлов:

```text
demo/mock/
├── summary.json
├── experiments.json
├── sample_efficiency.json
└── reconstructions/
    └── demo-pca-001.json
```

Каждый набор артефактов должен содержать все обязательные файлы.

Отсутствие любого обязательного файла считается ошибкой.

---

# 4. Канонические названия каналов

Поддерживаются только следующие обозначения метеорологических переменных.

| Канал | Описание | Единицы измерения |
|--------|----------|-------------------|
| u10 | Зональная скорость ветра на высоте 10 м | m s**-1 |
| v10 | Меридиональная скорость ветра на высоте 10 м | m s**-1 |
| t2m | Температура воздуха на высоте 2 м | K |
| msl | Давление на уровне моря | Pa |
| sst | Температура поверхности моря | K |
| tcc | Общая облачность | 0–1 |
| tcwv | Полное содержание водяного пара | kg m**-2 |
| tp1h | Осадки за 1 час | m |

## Запрещённые обозначения

Следующие имена использовать запрещено:

- mslp
- tp6h

Backend **не должен автоматически преобразовывать**:

```
tp1h → tp6h
```

или наоборот.

---

# 5. Единицы измерения

Backend обязан проверять соответствие единиц измерения выбранному каналу.

| Канал | Обязательные единицы |
|--------|----------------------|
| u10 | m s**-1 |
| v10 | m s**-1 |
| t2m | K |
| msl | Pa |
| sst | K |
| tcc | 0–1 |
| tcwv | kg m**-2 |
| tp1h | m |

# 6. Артефакт Summary

Файл:

```
summary.json
```

Содержит общую информацию о наборе экспериментов.

## Пример

```json
{
    "is_demo": true,
    "experiment_count": 1,
    "completed": 1,
    "failed": 0,
    "generated_at": "2024-01-02T15:00:00Z"
}
```

## Поля

| Поле | Тип | Описание |
|------|-----|----------|
| is_demo | boolean | Признак демонстрационных данных |
| experiment_count | integer | Общее количество экспериментов |
| completed | integer | Количество успешно завершённых экспериментов |
| failed | integer | Количество завершившихся с ошибкой |
| generated_at | datetime | Время формирования артефакта |

---

# 7. Артефакт Experiments

Файл:

```
experiments.json
```

Содержит описание всех экспериментов.

## Пример

```json
{
    "id": "demo-pca-001",
    "name": "Demo PCA baseline",
    "model": "pca",
    "status": "completed",
    "is_demo": true,
    "compression": {
        "type": "tensor_ratio",
        "ratio": 32
    },
    "training": {
        "sample_count": 168,
        "selection_strategy": "contiguous"
    },
    "metrics": {
        "normalized_rmse": 0.12,
        "mae": 0.08
    }
}
```

## Compression

| Поле | Тип |
|------|-----|
| type | string |
| ratio | integer |

## Training

| Поле | Тип |
|------|-----|
| sample_count | integer |
| selection_strategy | string |

## Metrics

| Поле | Тип |
|------|-----|
| normalized_rmse | float |
| mae | float |

---

# 8. Артефакт Sample Efficiency

Файл:

```
sample_efficiency.json
```

Содержит результаты исследования зависимости качества модели от количества обучающих примеров.

## Предлагаемая структура

```json
{
    "is_demo": true,
    "metric": "normalized_rmse",
    "points": [
        {
            "sample_count": 64,
            "value": 0.21
        },
        {
            "sample_count": 128,
            "value": 0.17
        }
    ]
}
```

---

# 9. Artifact Reconstruction

Каждый файл реконструкции содержит результаты восстановления одного или нескольких метеорологических полей.

Пример:

```json
{
    "experiment_id": "demo-pca-001",
    "channel": "t2m",
    "units": "K",
    "timestamp": "2024-01-02T12:00:00Z",
    "latitude": [],
    "longitude": [],
    "original": [[]],
    "reconstruction": [[]],
    "absolute_error": [[]],
    "is_demo": true
}
```

## Поля

| Поле | Тип |
|------|-----|
| experiment_id | string |
| channel | string |
| units | string |
| timestamp | datetime |
| latitude | array |
| longitude | array |
| original | matrix |
| reconstruction | matrix |
| absolute_error | matrix |
| is_demo | boolean |

---

# 10. Правила валидации

Backend обязан проверять:

- корректность JSON;
- наличие всех обязательных полей;
- соответствие Pydantic-схемам;
- существование указанного experiment_id;
- использование только канонических названий каналов;
- соответствие единиц измерения выбранному каналу;
- одинаковые размеры массивов:
  - original;
  - reconstruction;
  - absolute_error;
- соответствие количества широт числу строк массива;
- соответствие количества долгот числу столбцов массива;
- наличие временной метки (timestamp);
- значение `is_demo == true` для всех демонстрационных артефактов.

Любое нарушение правил должно приводить к контролируемой ошибке backend.

# 11. REST API

Backend предоставляет следующие конечные точки.

| Метод | Endpoint |
|--------|----------|
| GET | /health |
| GET | /api/v1/summary |
| GET | /api/v1/experiments |
| GET | /api/v1/experiments/{experiment_id} |
| GET | /api/v1/sample-efficiency |
| GET | /api/v1/reconstructions/{experiment_id} |

Endpoint реконструкций поддерживает параметры:

- channel;
- timestamp.

Пример запроса:

```
GET /api/v1/reconstructions/demo-pca-001
?channel=t2m
&timestamp=2024-01-02T12:00:00Z
```

---

# 12. Ответы об ошибках

Типовые ответы:

| HTTP | Описание |
|------|----------|
| 404 | Эксперимент не найден |
| 422 | Недопустимое название канала |
| 422 | Запрошенный timestamp отсутствует |
| 500 | Отсутствует обязательный артефакт |
| 500 | Некорректный JSON |

Ответы backend **не должны** содержать:

- трассировки стека;
- локальные пути к файлам;
- переменные окружения;
- токены;
- секретные данные.

---

# 13. Версионирование

Текущая версия контракта:

```
v1
```

К обратно совместимым изменениям относятся:

- добавление новых необязательных полей;
- добавление новых метрик.

Любые несовместимые изменения требуют выпуска новой версии API.

---

# 14. Требования к демонстрационным данным

Каждый артефакт, расположенный в каталоге

```
demo/mock/
```

обязан содержать поле

```json
"is_demo": true
```

Демонстрационные данные:

- не являются результатами реальных экспериментов;
- не должны позиционироваться как производственные результаты;
- используются исключительно для разработки и тестирования backend и frontend.

# Возможные направления развития

Контракт проектируется с учётом дальнейшего расширения.

В последующих версиях могут быть добавлены:

- дополнительные метрики качества;
- несколько временных меток в одном файле реконструкции;
- параметры обучения моделей;
- метаданные происхождения данных (provenance);
- пользовательские теги экспериментов;
- идентификаторы версии набора данных.

По возможности подобные изменения должны сохранять обратную совместимость.
