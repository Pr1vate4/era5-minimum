# Руководство по запуску и передаче проекта

Этот документ описывает, как запустить проект у другого участника или
организатора и как приложить модель к финальной версии, не помещая checkpoint
в Git.ъ

## Что нужно для запуска

- Git;
- Docker Engine и Docker Compose v2;
- свободные порты `5173` и `8000`;
- архив модели, приложенный к GitHub Release.

GPU для демонстрации сайта и инференса N32 не нужен.

## Запуск сайта и API

```bash
git clone https://github.com/Pr1vate4/era5-minimum.git
cd era5-minimum
git checkout <тег-финальной-версии>
cp .env.example .env
make docker-config
make docker-build
```

Скачайте asset модели из страницы соответствующего GitHub Release в корень
репозитория. Для текущего N128 имя файла должно быть
`era5-minimum-n128-model.zip`.

```bash
sha256sum era5-minimum-n128-model.zip
make model-unpack
make app-up
```

После этого откройте:

- сайт: <http://localhost:5173>;
- документацию API: <http://localhost:8000/docs>;
- состояние установленного кодека:
  <http://localhost:8000/api/v1/codec/status>.

Дополнительные диагностические команды:

```bash
make app-health
make app-logs
make app-down
```

Если порт занят, остановите ранее запущенный сервис, использующий этот порт,
либо укажите другой порт до запуска: `API_PORT=8001 make app-up`.

## Проверка модельного архива

У текущего поставляемого N128 pilot-а:

| Поле | Значение |
| --- | --- |
| Имя asset | `era5-minimum-n128-model.zip` |
| Размер ZIP | 845 389 байт |
| SHA-256 | `7268693a20503a72e4a2eb3e5e0ec11edb2dea015b6f3c73958b1f48152e0231` |
| Обязательные файлы | `model.ckpt`, `normalization_train_only.json` |
| Дополнительные отчёты | `metrics.json`, `report.json`, `first_test_frame.bitstream`, конфигурация обучения |

Команда `make model-unpack` откажется перезаписывать уже установленную модель
и проверит наличие двух обязательных файлов. После распаковки модель хранится
в игнорируемом Git каталоге `artifacts/model-n128/` и монтируется в API только
для чтения.

## Как закрепить финальную поставку

Не выполняйте `git add` для ZIP, checkpoint, `artifacts/`, ERA5-данных или
`outputs/`: это запрещено правилами проекта, даже если файл сейчас небольшой.
Вместо этого зафиксируйте две связанные, но разные сущности:

1. **Git-тег** — неизменяемая версия кода, конфигураций и документации.
2. **GitHub Release** к этому тегу — страница поставки с ZIP-моделью как
   отдельным asset и её SHA-256.

Перед созданием релиза на чистой рабочей копии выполните:

```bash
git status --short
make verify
make docker-config
```

Затем создайте и отправьте аннотированный тег. Имя ниже — пример; используйте
следующий свободный номер релиза.

```bash
git tag -a v0.1.0 -m "Финальная поставка ERA5-Minimum"
git push origin v0.1.0
```

На GitHub откройте **Releases → Draft a new release**, выберите тег `v0.1.0`,
загрузите `era5-minimum-n128-model.zip` в **Attach binaries** и в тексте релиза
укажите:

```text
Модель: era5-minimum-n128-model.zip
SHA-256: 7268693a20503a72e4a2eb3e5e0ec11edb2dea015b6f3c73958b1f48152e0231
Фактический статус: N128 pilot, не финальная приёмка по всем пунктам ТЗ.
Запуск: docs/DELIVERY_GUIDE.md
```

После публикации скачайте ZIP с Release на другой машине, сверьте SHA-256 и
пройдите команды из раздела «Запуск сайта и API». Так подтверждается, что
прикреплён именно тот файл, который запускает закреплённая версия кода.

## Что передавать организаторам

- URL Git-тега и GitHub Release;
- ZIP-модель как Release asset и её SHA-256;
- ссылку на это руководство;
- [RESEARCH_STATUS.md](RESEARCH_STATUS.md) с фактическими ограничениями;
- результаты финальной приёмки, когда она будет выполнена: manifests, метрики,
  bitstream, графики и ресурсный отчёт — отдельно от Git, с checksum и
  привязкой к тому же тегу.
