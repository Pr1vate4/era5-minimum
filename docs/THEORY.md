# Теория, необходимая команде

Актуальная схема тестовых ERA5 данных, channels, units и ограничений определена в [DATA_CONTRACT.md](DATA_CONTRACT.md).

## ERA5

ERA5 — реанализ: глобальная согласованная оценка состояния атмосферы, полученная объединением физической модели и наблюдений. Один временной срез содержит несколько пространственных полей на широтно-долготной сетке.

Каналы текущего raw contract:
- `t2m` — температура воздуха на высоте 2 м;
- `msl` — давление, приведённое к уровню моря;
- `u10`, `v10` — компоненты ветра на 10 м;
- `tp1h` — каноническое имя текущего loader output для raw `tp`;
- `sst` — температура поверхности моря;
- `tcwv` — суммарное содержание водяного пара в колонне;
- `tcc` — общая облачность.

Поля имеют разные единицы, диапазоны и распределения. Их нельзя обучать на общей сырой шкале без нормализации.

`tp1h` не является `tp6h`: последнее допустимо только после отдельной агрегации шести последовательных часовых значений.

## Автокодировщик

Encoder преобразует многоканальную карту `x` в компактный latent `z`; decoder восстанавливает `x_hat`.

Минимизируется distortion loss, например MSE. Простая MSE недостаточна для редких экстремумов и переменных с разными масштабами, поэтому нужны нормализация, метрики по каналам и затем специализированные loss-компоненты.

## Сжатие 32–64×

Есть три разных понятия:

1. **Tensor ratio** — число исходных значений / число latent-значений.
2. **Raw byte ratio** — байты исходного float32 / байты сохранённого latent с заданной точностью.
3. **Bitstream ratio** — размер реального закодированного файла после квантизации и энтропийного кодирования.

На защите нельзя выдавать первое за третье.

Для входа `[C,H,W]` и latent `[L,H/8,W/8]`:
- при `C=8`, `L=16` tensor ratio = 32×;
- при `C=8`, `L=8` tensor ratio = 64×.

## Метрики

### RMSE и MAE

Считать:
- в нормализованном пространстве — для оптимизации/диагностики;
- в физических единицах — для интерпретации;
- отдельно по каждой переменной.

### Latitude-weighted RMSE

На регулярной lat-lon сетке площадь ячейки уменьшается к полюсам. Вес строки приблизительно пропорционален `cos(latitude)`, иначе полярные области получают чрезмерный вес.

### Экстремумы

Для осадков и других тяжёлохвостых полей средняя ошибка может скрывать провал на редких событиях. Нужны percentile/extreme metrics: ошибка на верхних 1%, 5% или превышениях физического порога.

## Sample efficiency

Вопрос кейса: какое минимальное N достаточно? Недостаточно обучить модели на разных N. Нужно определить критерий достаточности.

Рекомендуемое правило:
- выбрать допустимый порог относительно качества модели на максимальной выборке;
- минимальным считать первое N, у которого качество находится не дальше заданного допуска и стабильно для следующего размера.

Пример: `N*` — минимальное N, где weighted RMSE не хуже более чем на 5% от full-data baseline и улучшение при удвоении N меньше 1%.

Это рабочая гипотеза, которую необходимо согласовать с организаторами.

## Главные угрозы валидности

- временная утечка;
- статистики нормализации, посчитанные на всём датасете;
- сравнение моделей при разном числе optimizer steps;
- единственный seed;
- общий RMSE, скрывающий плохие отдельные поля;
- неучтённые маски суши/океана для SST;
- неправильная обработка накопленных осадков;
- объявление теоретического latent ratio реальным файловым сжатием.
