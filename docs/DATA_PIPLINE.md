# Контракт и спецификация конвейера реальных данных ERA5-28ch (SSoT)
**Проект:** ERA5-Minimum  
**Версия:** 1.0.0 (Release: Real Data)  
**Статус:** Single Source of Truth (SSoT) для всех компонентов системы.

## 1. Назначение и Статус
Настоящий документ является **единственным источником истины (SSoT)** относительно формата, структуры, содержания и правил обработки реальных метеорологических данных в проекте ERA5-Minimum. 

С момента публикации этого документа **все моки, синтетические данные и упрощённые допущения (например, 8 каналов, `tp1h`, сетка 361×720) считаются устаревшими**. Все смежные контракты (`ARTIFACT_API_CONTRACT.md`, `PCA_BASELINE.md`) и код должны быть обновлены для поддержки данной спецификации.

## 2. Глобальные изменения (Переход от моков к реальности)
В связи с переходом на реальные данные, вводятся следующие жесткие правила, отменяющие предыдущие моковые соглашения:
1. **Количество каналов:** Вместо 8 приземных каналов используется **строго 28 каналов** (8 приземных + 20 атмосферных).
2. **Осадки:** Канал `tp1h` (моковый) **запрещён**. Используется только `tp6h` (агрегация за 6 часов из WeatherBench2).
3. **Давление:** Канал `msl` (моковый) переименовывается в `mslp` (mean_sea_level_pressure) согласно официальной номенклатуре.
4. **Сетка:** Базовой сеткой является **0.25° (721×1440)**. Сетка 0.5° (360×720) получается исключительно методом *conservative remapping*.
5. **Атмосферные уровни:** Добавляются переменные `T, U, V, Z, Q` на уровнях `1000, 925, 850, 700` hPa.

## 3. Источник данных и доступ
### 3.1. Основной источник
**WeatherBench2 ERA5 Zarr**  
`gs://weatherbench2/datasets/era5/1959-2023_01_10-wb13-6h-1440x721_with_derived_variables.zarr`

### 3.2. Правила доступа
* Доступ осуществляется через `xarray`, `zarr`, `dask`, `gcsfs` (анонимное чтение).
* **Запрещено** скачивать весь архив ERA5 локально. Конвейер читает только необходимые переменные, уровни, timestamps и координаты.
* CDS (Climate Data Store) допускается только как резервный adapter, но не как основной путь.

## 5. Пространственная структура и Сетки
### 5.1. Сетка 0.25° (Нативная)
* **Размер:** 721 × 1440 (включает полюса).
* **Действия:** Запрещена интерполяция. Допускается только приведение dimension names, dtype (`float32`) и фиксация направления `latitude` (ascending/descending) в манифесте.

### 5.2. Сетка 0.5° (Целевая для ML)
* **Размер:** 360 × 720 (cell-centred grid).
* **Алгоритм:** Строго **first-order conservative remapping**.
* **Запрещено:** Bilinear, nearest neighbour, простое прореживание (coarsen).
* **Периодичность:** Должна учитываться глобальная периодичность longitude (wrap-around).

### 5.3. Океанская маска и SST
* **SST над сушей:** Должен содержать `NaN`.
* **Ремаппинг SST:** Используется masked conservative remapping:  
  `remapped_sst = remap(sst × ocean_fraction) / remap(ocean_fraction)`.
* Ячейки с `ocean_fraction` ниже порога остаются `NaN`. Заполнение нулями запрещено.

## 6. Временная шкала и Сплиты
### 6.1. Границы сплитов
* **Train pool:** 2014-01-01 — 2019-12-31
* **Validation:** 2020-01-01 — 2020-12-31
* **Test:** 2021-01-01 — 2021-12-31
* **Шаг:** Строго 6 часов (00:00, 06:00, 12:00, 18:00 UTC).

### 6.2. Вложенные обучающие наборы (Nested Subsets)
Для анализа sample-efficiency формируются наборы:  
`N ∈ {128, 256, 512, 1024, 2048, 4096, 8192}`

**Жесткие требования:**
1. **Строгая вложенность:** `subset_128 ⊂ subset_256 ⊂ ... ⊂ subset_8192`.
2. **Сезонный баланс (Round-Robin):** Каждый набор содержит равное количество кадров из сезонов DJF, MAM, JJA, SON (например, для N=128: ровно 32 кадра на сезон).
3. **Детерминированность:** Генерация через фиксированный `seed`. Перемешивание внутри сезонов.
4. **Изоляция:** В наборы входят *только* timestamps из Train pool.

## 7. Формат хранения (Zarr) и Манифест
### 7.1. Zarr-структура
* **Массив:** `data[time, channel, latitude, longitude]` (dtype: `float32`).
* **Chunking:** Оптимизирован под чтение патчей (например, `time: 1-4, lat: 180, lon: 180`). Запрещён один гигантский чанк.
* **Компрессия:** Zarr storage compression (например, Blosc) разрешён, но **не является** конкурсным neural compression. В metadata должно быть явно указано: `storage_compression_is_not_codec_result = true`.

### 7.2. Манифест (`manifest.json`)
Криптографический паспорт датасета. Должен содержать:
* `schema_version`, `dataset_id`, `created_at`.
* `channel_spec` (полный список 28 каналов с индексами и единицами).
* `splits` и `nested_subsets` (пути к JSON-индексам, их count и SHA256).
* `statistics` (пути к файлам статистик).
* `integrity` (SHA256 манифеста, индексов, весов ремаппинга).
* **Запрещено:** Хранить абсолютные локальные пути (только относительные/URI) для обеспечения воспроизводимости хешей.

## 8. Статистики и Нормализация
* **Scope:** Строго **Train-only** (2014-2019). Использование Val/Test для расчёта `mean`, `std`, перцентилей (0.5 и 99.5) **категорически запрещено** (Data Leakage).
* **Обработка NaN:** Статистики для `sst` считаются только по валидным океаническим точкам.
* **Алгоритм:** Потоковый (Welford или аналог через Dask), без загрузки всего массива в RAM.

## 9. Влияние на смежные контракты (Обязательно к исполнению, важный ToDo)

   * Список канонических каналов должен быть расширен с 8 до 28.

   * Коэффициенты сжатия (`n_components`) должны быть пересчитаны для 28 каналов.
   * Padding должен учитывать реальные размеры сеток (721×1440 или 360×720).
