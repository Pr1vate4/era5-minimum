# МетеоКод / ERA5-Minimum

Воспроизводимая исследовательская система для проверки, какой минимальный объём
обучающей выборки достаточен для сжатия глобальных 28-канальных полей ERA5 с
контролем физически осмысленной ошибки восстановления. Проект подготовлен для
задачи хакатона: автоэнкодер, сжатие 32–64×, точный бинарный поток, метрики и
интерактивная демонстрация.

> [!IMPORTANT]
> Репозиторий содержит проверенный **N32 pilot**, а не доказательство полного
> выполнения ТЗ. Пилот обучен на 32 фактических уникальных временных метках.
> Обозначение **«N128-equivalent»** допустимо только как организаторский зачёт
> N32 при наличии их явного подтверждения; оно не меняет фактический размер
> выборки в манифестах, метриках или коде.

## Текущий результат

| Показатель | Значение | Что именно измерено |
| --- | ---: | --- |
| Каналы | 28 | Канонический порядок и единицы — в [DATA_CONTRACT](docs/DATA_CONTRACT.md). |
| Сетка pilot-а | 0.5°, 360 × 720 | Глобальный кадр `float32`. |
| Размер выборки | 32 train / 16 val / 16 test | Фактические уникальные временные метки. |
| Шаги обучения | 2 560 | CPU pilot. |
| Параметры модели | 163 476 | Меньше лимита ТЗ в 20 млн параметров. |
| Tensor compression ratio | 32.0× | Отношение числа элементов исходного тензора и latent; не размер файла. |
| Serialized compression ratio | 135.67× | Размер исходного `float32`-кадра / размер реального битового потока. |
| Exact roundtrip | `true` | После entropy decode квантизованные символы совпадают точно. |
| Test NRMSE, все каналы | 0.1901 | 16 test-кадров, после inverse normalization. |
| Test NRMSE, surface / pressure | 0.1944 / 0.1857 | Отдельно по группам каналов. |

Точные артефакты и ограничения приведены в
[RESEARCH_STATUS.md](docs/RESEARCH_STATUS.md). Tensor и serialized ratio
намеренно разделены: первое характеризует форму latent, второе — фактический
размер самостоятельного bitstream.

## Соответствие ТЗ: что есть и что ещё требуется

| Требование | Состояние |
| --- | --- |
| 28 каналов, физические единицы, latitude-weighted метрики | Реализовано для pilot-а. |
| Самостоятельный encode → bitstream → decode | Реализовано; exact roundtrip подтверждён. |
| Лимит 20 млн параметров | Выполнен текущей моделью. |
| Глобальная сетка 0.5° | Pilot выполнен на 0.5°. |
| 0.25°, коэффициент 64× | Не завершены. |
| Лестница N=128…8192 | Не проведена; N32 не подменяется фактическим N128. |
| Фиксированные split 2014–2019 / 2020 / 2021 | Контракт и проверки есть; полный итоговый прогон на этих split ещё нужен. |
| VAEformer/reference, paired bootstrap, спектральные и экстремальные тесты, latent probe | Пока не являются подтверждёнными итоговыми результатами. |

Это исследовательская работа: финальная приёмка должна запускаться на
зафиксированных manifests и публиковать конфигурацию, seed, версию кода,
runtime, метрики по каждому каналу и реальные размеры файлов.

## Возможности

- Подготовка ERA5 и WeatherBench2: проверка схемы, координат, единиц, NaN,
  временных меток и происхождения данных.
- Train-only normalisation и защита от temporal leakage в manifests.
- Компактный 28-канальный автоэнкодер, квантизация и entropy coding с
  независимым декодированием bitstream.
- RMSE/MAE/NRMSE в физических единицах, с весами `cos(latitude)`, разбивкой по
  каналам и группам surface/pressure.
- FastAPI для проверки модели и пользовательского сжатия NPZ-файла.
- Интерактивный Three.js-глобус: вращение, масштабирование, выбор времени и
  атмосферных слоёв, инспектор точки и слой облачности.
- Отдельная кнопка Grafana для операционных метрик API; графики качества
  сжатия во фронтенде должны использовать только экспортированные результаты
  конкретного запуска, а не демонстрационные значения.

## Быстрый старт

Официальная версия Python проекта — 3.12.

```bash
git clone https://github.com/Pr1vate4/era5-minimum.git
cd era5-minimum
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,api]"
make verify
```

`make verify` запускает тесты и небольшой воспроизводимый smoke-сценарий. Он
не скачивает ERA5 и не обучает финальную модель.

### Запуск сайта и API

```bash
cp .env.example .env
make docker-config
make docker-build
make app-up
```

После запуска доступны:

- сайт: `http://localhost:5173`;
- API и OpenAPI: `http://localhost:8000/docs`;
- status кодека: `http://localhost:8000/api/v1/codec/status`.

Полная инструкция для контейнеров и мониторинга — в [DOCKER.md](docs/DOCKER.md).

## Использование обученной модели

Checkpoint, исходные ERA5-данные, outputs и ZIP с моделью намеренно не
хранятся в Git. Чтобы команда могла использовать переданный архив модели,
положите его в корень репозитория и выполните:

```bash
make model-unpack
make app-up
```

Команда распаковывает модель в игнорируемый `artifacts/model-n32/`.
Проверьте её доступность:

```bash
curl http://localhost:8000/api/v1/codec/status
```

### Пользовательское сжатие через API

API принимает NPZ размером до 64 MiB с массивом `float32` формы
`[1, 28, 360, 720]`. Порядок каналов должен точно совпадать с data contract.
POST создаёт задачу и реальный bitstream; по идентификатору задачи доступны
реконструкция, preview, поток и метрики. Это рабочая демонстрация N32 pilot-а;
не следует выдавать её результат за итоговую оценку полного benchmark-а.

## Научная методология

1. Зафиксировать каналы, единицы, сетку и маски согласно
   [DATA_CONTRACT.md](docs/DATA_CONTRACT.md).
2. Сформировать непересекающиеся временные split с embargo; fit нормализации
   выполнить только на train.
3. Обучить модель по каждому размеру выборки с неизменяемыми config и seed.
4. На test выполнить полный `encode → bitstream → decode`; не оценивать
   «сжатие» только по размеру latent.
5. Выполнить inverse normalization и посчитать latitude-weighted метрики в
   физических единицах для каждого канала.
6. Сохранить manifest, config, commit, параметры, runtime, checkpoint hash,
   размеры артефактов и результаты в воспроизводимом отчёте.
7. Сравнить с reference и статистически проверить критерии ТЗ.

Команды и критерии финальной приёмки приведены в
[ERA5_MODEL_ACCEPTANCE_RUNBOOK.md](docs/ERA5_MODEL_ACCEPTANCE_RUNBOOK.md).

## Безопасность Git

Не добавляйте в коммит ERA5-файлы, checkpoints, ZIP-модели, `artifacts/`,
`outputs/`, секреты CDS и большие generated assets. Перед коммитом проверяйте:

```bash
git status --short
git diff --cached --stat
```

Большие модели и данные передаются отдельно от репозитория вместе с checksum,
версией кода и инструкцией воспроизведения.
